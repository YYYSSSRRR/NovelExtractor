# web-extract：站点无关的通用网页抽取 + 并发爬虫

小米 MiMo 数据架构工程师面试题**进阶（选做）**的交付物：不用题目下发的小说数据集，
自己写爬虫从互联网下载 1000+ 个网站的页面（新闻、问答、论坛、政府、教育、企业等多种
样式），抽出每页的 `real_title` 与 `main_content`。基础题的 stdin/stdout 接口同样实现。

**一句话做法**：纯 Go、零机器学习、零人工标注。爬虫用 **per-host 队列 + 就绪最小堆**，
一个结构同时拿到「每域串行 / 全局并行 / 礼貌限速 / 背压」；抽取器**不读任何 class/id
字符串**，只用文本密度、标点率、链接密度、DOM 结构做无监督打分，再用**域名级**的跨页
统计补足单页判断不了的部分。

跑出来的数（都在第四节，每个数字都注明了可不可复算）：

- 全量 **1067 个种子域 / 12183 页 / 16 分 30 秒**，进程自己干净收尾；
- 基础题数据集 **3473 页**一次跑批，空正文 **12.9%**，产物入库可校验 md5；
- 66 个测试函数全绿，`go vet` / `gofmt` 无输出。

## 一、怎么跑

### 构建

```bash
go build -o bin/crawler   ./cmd/crawler
go build -o bin/extractor ./cmd/extractor
go build -o bin/seeds     ./cmd/seeds
go build -o bin/eval      ./cmd/eval
```

### 基础题接口

```bash
./bin/extractor < input.jsonl > output.jsonl      # {url,html,title} → {url,meta_title,real_title,main_content}
./bin/extractor -stats < input.jsonl > /dev/null  # 汇总指标打到 stderr
```

- **输入几行就输出几行**：坏 JSON 行也占一格（四个字段全空），不静默丢行。
- stdout 只有 JSON，`-stats` 只往 stderr 写，所以重定向到文件是干净的。
- 消融开关：`-no-punct`、`-no-link`、`-no-propagate`、`-no-cross-page`、`-keep-attribution`。

对题目下发的数据集（`data/novel.json`，126MB，不入库）跑一轮：

```bash
./bin/extractor -stats < data/novel.json > data/novel_out.jsonl
```

产物入库，同一份输入两次跑逐字节相同。结果见 [4.1](#41-基础题数据集全量跑批)。

### 爬虫

```bash
# -data 一定要指向空目录或专门的数据目录：store 是 O_APPEND 追加写，
# 启动时还会做一次破坏性截尾行。用仓库自带的 data/ 会把上万行追加到交付语料后面。
./bin/crawler -data /tmp/fullrun -seeds seeds/seeds.txt \
          -workers 32 -delay 1500ms -budget 30 -per-host 15 \
          -trace /tmp/fullrun/requests.trace
```

| 参数 | 默认 | 含义 |
|---|---|---|
| `-workers` | 32 | 并发 worker 数（= 同时在抓的不同域数） |
| `-delay` | 1500ms | 同一域名两次请求的最小间隔 |
| `-timeout` | 20s | 单次请求超时 |
| `-budget` | 12 | 每域抓取总预算（含首页与栏目页） |
| `-per-host` | 5 | 每域目标正文页数，0 为不限 |
| `-min-content` | 300 | 判为正文页的最小正文长度 |
| `-max-link-rate` | 0.3 | 判为正文页的最大正文链接密度 |
| `-max-host-failures` | 2 | 连续这么多次失败就放弃该域剩余队列，0 为关闭 |
| `-max-pages` | 0 | 全局页数上限，0 为不限 |
| `-max-bytes` | 5MB | 响应体上限 |
| `-retries` | 0 | 单个 URL 的失败重试次数，0 表示抓不到就跳过 |
| `-trace` | 空 | 逐行记录每次请求的发起时刻，用于验证每域请求间隔 |
| `-no-templates` | false | 消融：关闭跨页模板过滤 |

中断后重跑同一条命令即续爬。`Crawl-delay` 超过 60 秒的站会被整个放弃（照做结束不了，
不照做又不诚实，第三条路是不去），日志里打一行 `Crawl-delay %s 超过上限 %s，放弃该域`。

## 二、抽取算法（核心逻辑）

**铁律：不读 class/id。** 全程不出现 `ptm-content`、`chapter-content` 这类选择器，也不
出现 `novel`/`chapter` 这类站点先验词。判据只有三类：元素自身的 HTML 语义（`<article>`、
`<nav>` 是标准，任何站点含义一致）、文本统计量、DOM 结构。

```bash
$ grep -rnE "novel|chapter|ptm-|wenku" internal/extract/*.go | grep -v _test.go | grep -v '//'
（无输出）
```

（唯一一处命中是测试夹具里一个 `class="novelinfo"`——它存在的意义正是验证算法不看它。）

### 2.1 meta_title

`<head><title>` 的纯文本，折叠空白，取第一个。无歧义。

### 2.2 real_title：候选打分 + 跨页站点后缀学习

用户在页面上看到的标题，难点在于 `<title>` 几乎总被污染成 `文章标题-栏目-站点名`。

**候选收集**：第一个非空 `<h1>` 的直接文本、`og:title` / `twitter:title`、JSON-LD 的
`headline`、以及 `<title>` 按分隔符切分后的**所有前缀组合**。分隔符是
`| - – — _ / \ » « ~`，**刻意取窄**：`：`、`，`、`、`、`·` 不是分隔符，它们是标题正文
的一部分（`习近平：坚持和发展中国特色社会主义`），拿来切会把标题切坏。`-` 则要宽容，
所以 `A-B-C-D` 保留 `A` / `A-B` / `A-B-C` / `A-B-C-D` 全部前缀，而不是只取第一段。

**跨页站点后缀学习**（`internal/extract/chrome.go`）是这套方案最能体现「数据架构」的
一招。站点名后缀是**域名级常量**，不是页级性质，而爬虫手里有每域十几到上百页：

```
学习 = 求该域名所有 <title> 的最长公共前后缀（逐位多数投票，≥60% 页面共现）
应用 = 从标题两端剥掉它们
```

不需要站点名单、不需要正则、不知道体裁，而且页数越多越准。单页永远分不清
「我的明星老婆免费章节(花枫年华)」里哪一截是书名——它和章节名之间连分隔符都没有，
任何切分规则都切不开；跨页一看它每页都在，立刻暴露。两个细节是有原因的：

- **逐位多数投票**而不是两两求最长公共前缀：后者只要有一页异类就会把结果拉到极短。
- **收缩到分隔符边界**：逐位投票只知道哪些字符每页都一样，不知道词边界在哪。不收缩会
  切在词内部——实测踩到过：某域所有章节标题都以「第」开头，「第」被当成前缀剥掉，
  「第三百八十四章大凶」变成「三百八十四章大凶」。

**打分**：候选**不是**按可信度取第一个，而是全部进池打分（h1 有时是栏目标题，
og:title 有时反而是运营编辑过的）。

```
score = 来源先验（og:title 1.00 / twitter 0.95 / JSON-LD 0.90 / h1 0.85 起每层递减 0.05
                / <title> 切分出的段 0.30 起递减 / 剥离后的整串 0.25 / 未剥离的 0.10）
      + 1.0 × 与正文前 200 字的 bigram 重合率     # 权重最高的一项
      + 0.5 × titleAffinity(候选, <title>)        # 前缀 1.0 / 相同 0.5 / 子串 0.6
      + 0.2 × lengthFit(长度)                     # [4,60] 满分，[61,120] 减半
      − 1.5 × 命中已学站点前后缀
```

**与正文的重合度权重最高**，理由很难被模板伪造：站点名、栏目名不会出现在正文段落里，
而真实标题几乎总在正文开头被重复一次。长度不在 `[4,120]` 的候选直接出局。
**绝不使用章节号正则**——那是小说专属，正是要摆脱的东西。

### 2.3 main_content：文本密度打分 + 祖先累积

核心洞察：**正文区和导航区的区别不在名字，而在统计形态**。正文是高字符密度、高标点
密度、极低链接密度；导航恰好相反。

**Step 1 树预处理** 丢弃 `<script> <style> <noscript> <iframe> <svg> <form> <button>
<select> <textarea>` 与注释，丢弃 `<nav> <aside> <footer>`。（用 HTML5 语义标签是合法
的——它们是标准，不是站点特征。`<header>` 保留，因为有些站把 h1 放里面。）

**Step 2 统计量** 对每个块级元素（`p div article section td th blockquote li pre dd
figcaption`）数四个量：字符数 `T`、元素个数 `E`、标点数 `P`、`<a>` 后代字符数 `L`。

**Step 3 块打分**，四个因子相乘，任一不满足即被压制：

```
textDensity = T / (E + 1)                 字符/标签——导航区标签多、文字少
punctGate   = min((P/T) / 0.15, 1.0)      标点率归一化，15% 即满分
linkRate    = L / T                       链接密度，导航/列表/标签云的照妖镜
lengthGate  = min(T / 200, 1.0)           太短的块不可能是正文

score = log1p(textDensity) × (0.2 + 0.8×punctGate) × (1 − linkRate) × lengthGate
```

量纲感受：100 字的 `<p>`，density≈50、punctRate≈0.12、linkRate=0 → score≈2.9；
50 条链接的导航 div，density≈4、linkRate≈0.9 → score≈0.14。**相差 20 倍**。乘性组合
而不是加权求和是刻意的：加权求和下只要某一项极高就能掩盖其余项的缺陷，而正文必须四项
同时成立。

**Step 4 祖先累积**（Readability 的精髓）：

```
accum(n) = own(n) + Σ own(直接子块) + 0.5 × Σ own(孙块)
```

只向上汇入两层。若沿祖先链无限累加，最外层的整页 wrapper 必然因「包含所有内容」胜出，
正文容器就永远选不出来——这是 naive 实现的典型失败模式。

但两层折半挡得住无限上溯，挡不住**一轮聚合**：`own` 只对候选块填过值，
`<body>`/`<html>`/`<ul>`/`<tr>` 这些结构元素的 `own` 恒为 0，可它们照样能从直接子块
拿满学分。于是当正文容器**没有块级子元素**时（正文用 `<br>` 分段而不是 `<p>`，移动端
小说站几乎都是这个写法），双方就调了个个儿：

```
<div class=content>  accum = own(自己)             = 3.32
<body>               accum = 0 + own(content) + … = 4.08   ← 赢了
```

`<body>` 赢了之后被 Step 6 按判据一（容器是 html/body）**正确地**判成「这一页没有
正文」，正文其实好端端地在第二名待着。所以当选资格与累积拆开：**`accum` 谁都算，但只有
`own > 0` 的元素才有资格当选**，结构容器只负责被 Step 5 上溯进去。

这个形状在 `data/novel.json` 的 801 页抽样里占 **63.9%**（其中 `<body>` 独占 429 页），
是修复前 66.4% 空结果的主因；修完降到 12.9%。见 [4.1](#41-基础题数据集全量跑批)。

**Step 5 容器上溯**：父节点累积分 ≥ 自身 × 0.75（`climbRatio`）且链接密度没有明显恶化
（允许 +0.10）时取父节点，循环直到不满足。这解决「正文被多包了一层 wrapper」的常见
情况。上溯同时也是 Step 4 那条资格判据**不会改坏原有结果**的保证：一个结构容器当初能
赢，就说明它的累积分不低于任何一个子块，从子块出发的上溯阈值必然满足，会原路爬回同一
个容器。实测印证：修复前后 1168 页有正文的页面**逐字节相同，0 页缩水、0 页变成空**。

**Step 6 判定与文本输出**：先按四条结构性判据判「这一页到底有没有正文」——容器是
`html`/`body`（没有任何子区域在竞争中胜出）、容器是非散文元素（`ul`/`table`/`header`…）、
链接密度 > 0.5、短到不成句（< 80 字）。判掉了就交白卷，而不是把整页样板以「正文」的
名义交出去。然后按文档序遍历容器，块级边界插 `\n`；跳过整块链接密度 > 0.5 的子块
（吃掉残留的「相关阅读」「上一篇」），但**只对块级元素判**——行内 `<a>` 自身链接密度
天然接近 1，套同一条规则会把正文里的内联链接连文字一起删掉，句子从中间断掉。

**Step 7 归一化**：折叠空白、丢空行、删署名行（短行 + 含 URL）；删掉开头与 `real_title`
重复的行，判据是归一化后的包含关系**加长度约束**——不带长度约束的「包含」会退化成
「正文里只要提到标题就删」，而新闻页常在第一段复述标题，那样会整段吃掉。

### 2.4 跨页模板过滤

同一域名下反复出现的文本，按定义就不是这篇文章的内容。手段是统计而非词表：

```
对某域名的 N 篇正文：统计字符 5-gram 的文档频率
出现在 ≥50% 页面（且至少 3 页）中的 5-gram → 判为模板片段
逐行找出连续被覆盖 ≥8 字符的区段，切掉；切完该行没剩什么就整行丢弃
安全闸：单页剥除超过一半就整页放弃，宁可留原文也不交残缺正文
```

判据是**文档频率**而不是词频，这个区分是关键：一个片段在一页里出现 100 次说明它在重复
自己（那可能正是正文的修辞），在 100 页里的 60 页各出现 1 次才说明它是站点模板。

### 2.5 为什么这套东西能泛化

三个机制各自都不依赖「这是什么站」：打分量是**统计形态**（小说、新闻、问答的正文在这些
量上长得一样）；站点模板是**学出来的**而不是配出来的（页数越多越准）；模板残留是
**语料驱动**的（无标注、无规则）。代价是每个机制单独看都不精确，三个叠起来的成绩见第四节。

## 三、爬虫（核心逻辑）

### 朴素做法错在哪

直接开 500 个 goroutine 抢一个 URL channel，会同时向同一个站发几十个并发请求，几分钟内
被 ban。**「全局并发」和「每域礼貌」是正交的两个约束，必须分开管。**

### 设计：per-host 队列 + 就绪最小堆

```
Frontier
  queues  map[host]*hostQueue   host → FIFO URL 队列
  heap    hostHeap              最小堆，按 nextAt（该域下次可请求的时刻）排序
  ready   chan Task             cap = worker 数
  seen    map[uint64]struct{}   URL 规范化后的 hash，去重

调度循环（单协程）:
  取堆顶；若 nextAt 未到 → 睡到那个时刻（有新域入堆则重新判定）
  弹出，从该域队列取一条 URL，交给 ready；ready 满则阻塞 —— 天然背压

worker:
  for host := range ready { 取该域队列头部 → 抓取 → Done(host)（nextAt = now + delay）→ 重新入堆 }
```

一个结构同时拿到四个性质：

| 性质 | 如何得到 |
|---|---|
| **每域严格串行** | 一个 host 要么在堆里、要么在某个 worker 手里，不可能同时在两处 |
| **全局并行** | ready 由 N 个 worker 消费，不同 host 天然并行 |
| **礼貌限速** | 时间门控下沉进堆，`nextAt` 是唯一真相源，业务代码里没有散落的 sleep |
| **背压** | ready 有界，堆满即阻塞调度器，不会无限堆积 URL |

### 时间闸：一个 worker 的时间片里可能有多个请求

上表保证的是**任务**级串行，但一个 worker 在自己的时间片内可能发出不止一个请求：某域的
第一次访问要顺带拉 `robots.txt`，拉不到还得换协议重试。`-trace` 实测到过 32 对间隔低于
配置值的请求，**全部是 robots.txt 与紧随其后的页面请求**。

修法不是在那条分支上补一个 sleep，而是给 frontier 加 `Gate`：**任何**发往某域的请求都要
先过它，`nextAt` 依然是唯一真相源。爬虫侧的 `doGet` 成为唯一的请求出口（`grep -n
client.Get` 只有一处命中），`Gate` 与 trace 记录绑在同一个函数里，于是「每个请求都受限速
约束、且每个请求都留痕」从「靠调用方自觉」变成了结构上的保证。`robots.txt` 的
`Crawl-delay` 能一行接进来也正是因为限速只有一个真相源，且只接受比全局间隔更大的值。

### 什么时候可以不抓了：三条收手路径

按域礼貌限速意味着**域数 × 每域请求数 × 间隔 ÷ worker 数**就是系统的耗时，省下最后那一项
的办法是承认「够了就别抓了」。三条路径都只丢**队列**、不丢已经抓到的页面：

| 路径 | 触发条件 | 参数 |
|---|---|---|
| 已够数 | 本域正文页已达目标 | `-per-host`（0 为不限） |
| 连续失败 | 本域连续抓取失败到阈值 | `-max-host-failures`（默认 2） |
| 间隔过长 | 站点声明的 `Crawl-delay` 超过上限 | 固定 60s |

丢弃由 `frontier.Abandon(host)` 执行——只有调度器知道这个域还排着多少条。已经发出去的
那个任务不受影响：它在某个 worker 手里，收尾时照常 `Done`，而 `Done` 会看到空队列于是
返回 drained，**域级收尾与落盘照常发生**。这一条是「省时间不能以丢数据为代价」的落点。

### 每站抓什么：四级漏斗

不能靠写死 URL 正则挑正文页，但也不能盲抓。**便宜的先筛、贵的后验**：

1. **首页 + ≤2 个栏目页** → 抽同域链接，得 200–2000 条候选
2. **URL 粗筛**（纯 CPU、零成本）：路径深度 ≥2、含数字 ID 或日期，排除
   `login|search|tag|category|about|page=\d`，剩 50–200 条
3. **抓取限额**：每域最多 `-budget` 次请求
4. **抽取器精筛**：跑一遍 `extract`，保留「正文长度 ≥300 且链接密度 ≤0.3」的页面

第 4 步是**用抽取器自己做页面类型分类器**——复用同一套代码，不引入第二套站点知识。
这个自举设计比 URL 正则可靠得多，也和「泛化」的主题自洽。

### 域的边界上做跨页收尾

跨页统计是**域名级**的量，只有在这个域一页都不剩时才算得准；而调度器本来就是唯一知道
「这个域爬完了」的地方。所以 `frontier.Done(host)` 直接返回该域是否排空，爬虫据此在域的
边界上收尾：学模板、清洗正文、落盘。不落盘原文也能做跨页统计，靠的正是这条——同域的
页面本来就会在内存里陆续聚齐，用完即弃。

### 工程细节

- **编码统一**：`charset.NewReader` 一行覆盖 BOM、Content-Type 头与 `<meta charset>`
  三种来源，GBK/GB18030/Big5 都能转。
- **断点续爬**：`pages.jsonl` 记录已完成 URL，`queue.jsonl` 记录待抓队列。只持久化前者
  的话，kill -9 重启后内存里的待抓队列就没了，而已抓集合又会让所有种子被跳过，结果是什么
  都不做直接「爬完」。写了一半的尾行在重启时被截掉——它解析不出来，对应的页面必然重抓。
- **优雅退出**：`signal.NotifyContext`，SIGINT 停止调度、等在途请求、flush 产物。
- **UA**：单一诚实 UA + 联系方式，不轮换不伪装。

**有区分度的三个信号：**

1. **祖先累积**（平均长度 1195 → 632，单行输出占比 0.0% → 9.5%）。这是全套里最不能动的
   一步：正文从来不是**一个**块，而是一串并列的 `<p>`，单看任何一个都又短又没信息量。关掉
   传播就退化成「挑一个最像正文的块」，一篇文章只剩一段，9.5% 正是这个退化的指纹。
2. **链接惩罚**（空结果率 15.0% → 25.1%）。没有它，全局最高分会落到导航/列表容器上，而
   这个容器在输出阶段又会被 `linkRate > 0.5` 整块滤掉，最终交白卷——它决定的不是精度，
   是**有没有结果**。
3. **跨页模板过滤**（残留率 0.01% → 6.03%，约 600 倍）。纯语料驱动，没有词表、没有正则，
   效果却是全表里最悬殊的一个。

**两个诚实的负面结果：** 关标点率几乎无影响（15.0% ↔ 15.8%），因为它只在
`(0.2 + 0.8×punctGate)` 里起作用，那个 0.2 的底数意味着它只能把分数压到 1/5、压不到 0
——它**调整排序，但很少改变冠军**。关跨页标题学习在全部列上数字一模一样，因为这几条代理
指标**测不到它**：标题学习改的是标题的内容（剥掉 `-其他文库-轻小说文库` 这类后缀），而
「标题非空率」两种情况下都是 98.6%。**把「指标测不出」和「机制没作用」分开写，比给一个
好看的数字重要。**

### 4.5 交付语料 `data/pages.jsonl`（可复算）

抽样自 4.2 那一轮的产物，300 行 / 300 个域名 / 0 坏行。抽样规则在 `scripts/sample.py`：
按域分组、每域等距跨步取最多 2 页，展平后再跨步到 300 行，两步都不含随机数。同一份输入
两次跑出逐字节相同的输出，可以自己验：

```bash
$ md5 -q data/pages.jsonl
577444028f373a452566133e64b1a347
```

**语料存的是所有抓到的页面，不是只存文章页**，所以下面的构成要在「这份样本的构成」这个
意义上读：

```
行数 300 / 域名 300 / 坏行 0
空正文          166（55.3%）
content_chars ≥ 300   85（28.3%）
content_link_rate 恰好为 0    216（72.0%）    > 0.3 只有 6 行，max 0.48
正文非空却一个换行都没有       0 / 134
页脚残留（版权所有/ICP备/免责声明/Copyright/保留所有权利）   22（7.3%）
real_title 与 meta_title 的关系：前缀 120 / 中间 15 / 完全相同 106 / 后缀 21 / 不在其中 28 / 为空 10
```

两点要说清楚：

- **空正文率 55.3% 高于全量产物的 36.6%，是抽样规则抬上去的。** `--per-host 2` 让「只抓
  到 1 页」的稀疏域按满额计入，而全量里它们被每域 15 页的站摊薄了。这不是抽样写错了，是
  「每域限量」这个规则本身给稀疏域加权——想要样本忠实反映全量构成，就不该按域分层。
- **`content_link_rate` 没有区分度，不能当页面类型过滤器用。** 它在 72% 的行上恒为 0，这
  是抽取干净的表现（链接块在渲染阶段就被整块跳过了），不是字段坏了，但 `<=0.3` 因此几乎
  筛不掉任何东西。真正有区分度的只有 `content_chars`，而它单独用正是「菜单页只要够长就被
  当文章」那个老问题。想要文章页，得拿到 HTML 重跑抽取。

（22.8KB 页）与 **1906 页/秒**（42.5KB 页）。

分配剖析的结论比数字本身重要：**54.3% 的分配在 `golang.org/x/net/html` 建 DOM 上**（题目
指定必须用的库），我们自己的打分逻辑合计约 15%。也就是说**换掉打分算法最多省 15% 的分配**
——真正的杠杆不在能改的范围里。所以没有做「优化前后对比」：热点全在指定依赖和 runtime 里，
**这比编一个优化故事诚实**。

无论取哪个口径，抽取能力都比抓取能力快两个数量级以上：在按域礼貌限速的前提下，抽取开销
在架构上无关紧要。

### 4.7 测试（可复算）

```
$ go clean -testcache && go test ./...
ok  web-extract/cmd/crawler  ok  web-extract/cmd/extractor  ok  web-extract/internal/discover
ok  web-extract/internal/extract  ok  web-extract/internal/fetch  ok  web-extract/internal/frontier
ok  web-extract/internal/seed  ok  web-extract/internal/store
```

`go vet ./...`、`gofmt -l .` 均无输出。共 66 个测试函数（`cmd/crawler` 11、
`internal/frontier` 19、`internal/extract` 13、`internal/fetch` 8、`internal/seed` 6、
`internal/discover` 4、`internal/store` 3、`cmd/extractor` 2）。

**测试大多是回归测试，每一条都对应一个真实发生过的 bug**，注释里写了现场。最值得看的
四条：

- `cmd/crawler/stall_test.go` —— 一个只会超时的域必须在有限次失败之后被放弃，整轮爬取
  必须能自己结束。对应那次停在 `queue=1 inflight=0` 二十多分钟的事故。
- `cmd/crawler/shutdown_test.go` —— 调度器正睡在某个域远期的时间片上时收到 SIGTERM，
  worker 必须能在有限时间内退出来，好让内存里那批页面落盘。
- `internal/frontier/invariant_test.go` —— 随机并发下四条调度不变量，其中「`state=idle`
  的域必无 URL」就是那个事故的形状：有 URL 躺在一个不在堆里的域中，而三个公开计数怎么读
  都自洽。
- `cmd/extractor/contract_test.go` —— 与外部系统之间的接口约定：输入几行就输出几行
  （坏 JSON 也占一格）、每行恰好那四个字段、stdout 只有 JSON。另有一条给同域 4 页、
  **故意不给 `<h1>`**，断言每页的 `real_title` 都剥到只剩章节名——靠 `<h1>` 是单页特征，
  靠跨页统计才是这题要的泛化。

两个 bug 值得点名，因为它们都是「不实测就发现不了」的那一类：一次是 **`http.Client.Timeout`
在 HTTP/2 下不生效**（它靠连接级 deadline 取消，而 HTTP/2 的 `roundTrip` 走 stream 级的
select；设的 15s 实际挂了 2 分钟，靠 `kill -QUIT` 拿 goroutine 栈才看清），修法是关掉
HTTP/2 + 每个请求加 `context.WithTimeout`；另一次是 **robots.txt 不受每域限速约束**，
靠把 trace 逐对算间隔才现形，修法是给 frontier 加 `Gate`（见第三节）。

**明确不做的**（不是遗漏，是取舍）：机器学习 / 特征工程（岗位是数据架构，万亿级语料清洗

负期望）。
