# 基础题：`data/novel.json` 全量抽取

题目下发的小说数据集（`data/novel.json`，126MB，**不入库**）跑一遍抽取，
产物是 `data/novel_out.jsonl`——一行输入一行输出，逐行同序对齐。

```bash
go build -o bin/extractor ./cmd/extractor
./bin/extractor -stats < data/novel.json > data/novel_out.jsonl
```

`-stats` 往 stderr 打汇总，stdout 只有 JSON，所以重定向到文件是干净的。
输出可复现：同一份输入跑两次 md5 相同（`e1d56e337a34e873595197cfd83850de`）。

## 修的是什么

### 症状

`.asp` 那一族页面（棉花小说网、八仙小说网这类移动端小说站）**一页都抽不出来**，
可它们的正文好端端地在 HTML 里。1648 页 `.asp`，修复前只有 2 页出正文。

### 根因

`accumulate` 的累积分是这么来的：

```
accum(n) = own(n) + Σ own(直接子块) + 0.5 × Σ own(孙块)
```

两层折半是为了挡住「无限上溯到整页 wrapper」。但它挡不住**一轮聚合**：
`own` 只对 `isBlockCandidate` 的元素填过值，`<body>`、`<html>`、`<ul>`、
`<tr>` 这些结构元素的 `own` 恒为 0，可它们照样能从直接子块拿满学分。

于是当正文容器**没有块级子元素**时（正文用 `<br>` 分段而不是 `<p>`，
移动端小说站几乎都是这个写法），双方就调了个个儿。以
`https://m.mhuaxs.com/mianhuaxs.asp?id=509991` 为例，把 DOM 里的实际分数打出来：

```
 0 accum=  4.079 own=  0.000 chars= 2551 linkRate=0.024 /html/body
 1 accum=  3.317 own=  3.317 chars= 2404 linkRate=0.000 /html/body/div   ← 真正的正文容器
 2 accum=  1.882 own=  0.000 chars= 2583 linkRate=0.024 /html
```

`<body>` 自己一分没有，靠「正文容器 + 页眉 + 页脚 + 半层孙子」凑到 4.079，
赢了以自己一己之力参赛的 3.317。接着 `looksLikeArticle` 看到容器是 `body`，
按判据一（`容器是 html/body`）正确地判定「这一页没有正文主体」，正文就这么
被清空了——它其实在第二名待着。

这个形状在 801 页抽样里占 **63.9%**（其中 `<body>` 独占 429 页），是当时
66.4% 空结果的主因。

### 改法

当选资格与累计拆开：**`accum` 谁都算，但只有 `own > 0` 的元素才有资格当选**。
结构容器一个都不参选，它们的作用是被 `pickContainer` 上溯进去。

```go
// 参选资格只看 own：own 恒为 0 的元素（结构容器、纯导航块）不管聚合到
// 多少分都不能当选。
eligible := own[n] > 0
...
if eligible && (best == nil || a > accum[best]) {
    best = n
}
```

**它不可能改坏原本正确的页面**，理由是结构性的而不是统计出来的：一个结构容器
能赢，前提是它的 accum 高于任何一个子块；而 `pickContainer` 从子块出发上溯时，
判的就是 `accum[祖先] ≥ 0.75 × accum[起点]`——既然它当初能赢，这个条件必然满足，
上溯会原路爬回去。所以这类页面的最终容器与修复前**完全相同**，变的只是那些
「结构容器赢、然后被 `looksLikeArticle` 判掉」的页面。

实测印证了这一点：修复前后 1168 页有正文的页面对比，**逐字节相同，
0 页缩水、0 页变成空**；变动的全部是 1858 页「从无到有」。

### 钉住它的测试

`internal/extract/article_test.go` 的 `TestBrSegmentedArticleIsExtracted`：
一页正文只由 `<br>` 分段、前后各挂一份站点模板的章节页。断言两件事——
抽得出来（容器不是 `body`），以及抽得准（`<br>` 变成换行，页眉页脚的
「京ICP备」「下章」没有被裹进来）。去掉上面那条判据，这个测试立刻红。

## 还剩 12.87% 空

不打算粉饰：447 页仍然抽不出正文，而它们的整页可见文本中位数是 2053 字，
**不是空壳页**。5 个域名占了其中 403 页：

| 域名 | 空 / 总 |
|---|---|
| `www.8xianxs.com` | 141 / 147 |
| `m.lcread.com` | 120 / 120 |
| `m.lc1001.com` | 114 / 114 |
| `p.feilu.cc` | 17 / 27 |
| 其余 29 个域名 | 44 |

`m.lcread.com` 整站是 JS 渲染的空壳（首页只有 119 个中日韩字符），属于
「本实现不做 headless browser」那条边界，见 README 第一节。

`m.lc1001.com` 和 `www.8xianxs.com` 是另一回事，也是这里没解决的那个：
正文装在 `<div class=chapterContent>` 里，但**外面还套着一层有自己文字的候选
div**，于是「wrapper 的 own ≈ 正文的 own」这个更根本的问题浮出来——
`own` 是按整棵子树算的，wrapper 与它装的正文同分，再叠上子块的分就必然赢。

试过的改法是让 `own` 只算「刨掉直接子块之后自己那份文字」
（`textStats` 四个字段都是可加计数器，子块子树两两不相交，减法是精确的）。
在 3473 页上实测**更差**：空结果 12.87% → 13.65%，并且打红了既有的
`TestLinkOnlyBlockDropped`——`accum[best]` 变小之后 `pickContainer` 会上溯得
更远，把整页 wrapper 又捞回来。所以**没有采用**，代码里没有它的痕迹。

结论是这需要连同 `pickContainer` 的上溯口径一起重做，不是一行判据的事，
而重做必须配一套非小说的回归集才能确认没有把新闻侧改坏——手上只有
`data/novel.json` 这一份带原始 HTML 的大语料（爬取产物只存了 `html_sha1`，
正文 HTML 没有落盘）。所以这里如实记下，不动它。
